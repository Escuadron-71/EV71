# feat/i18n — Internacionalizacion ES/EN

## Objetivo

Evaluar e implementar la internacionalizacion del sitio a **Espanol (es) e Ingles (en)**.
Decision del equipo: **fase final, despues de estabilizar el contenido y las nuevas vistas**.
Esta rama arranca solo cuando las demas ramas de contenido esten en `dev`.

## Alcance

- Evaluar alcance de i18n (documento de factibilidad).
- Si se aprueba: arquitectura de traduccion + switcher de idioma + routing.
- El item "Idioma" del UserDropdown ya existe como placeholder en `Header.astro`.

## Opciones de arquitectura (a decidir en la evaluacion)

### A) Routing i18n de Astro (nativo)
- `astro.config.mjs` → `i18n: { defaultLocale: "es", locales: ["es", "en"], routing: { prefixDefaultLocale: false } }`.
- URLs: `/` (es) y `/en/...` (en). Cada pagina en `src/pages/` + `src/pages/en/` o
  con `getStaticPaths` + `Astro.currentLocale`.
- Compatible con `output: "static"` y GitHub Pages, **pero** el contenido de los `.md`
  (docs, cursos, blog) debe duplicarse o traducirse por locale.

### B) Diccionarios + param de URL (ligero)
- `src/lib/i18n/es.ts` / `en.ts` con cadenas clave/valor.
- Switcher guarda locale en localStorage + `?lang=en`; componentes leen las cadenas.
- Mas simple, pero el SEO de `/en/...` no existe (mismo HTML para todos) y el contenido
  largo (cursos, noticias) no se traduce bien.

### Recomendacion preliminar
- **A)** si el equipo se compromete a contenido bilingue real (SEO + versiones de paginas).
- **B)** como paso intermedio para UI/labels solamente.

## Fases / Subfases

### Fase 1 — Evaluacion y decision
1. Documento de factibilidad `docs/I18N.md` (local): inventario de cadenas (header,
   footer, home, operaciones, postulacion, planificador, dogfight), contenido largo
   (docs institucionales, cursos, blog) y coste de traduccion.
2. Decidir opcion A vs B y locales (`es`/`en`).
3. Definir estrategia de traduccion de contenido `.md` (duplicar coleccion con `locale`
   en frontmatter vs solo UI).

### Fase 2 — Infraestructura
1. `src/lib/i18n/`: diccionarios, helper `t(key)`, tipo `Locale`, `getLocale(pathname)`.
2. `astro.config.mjs`: config `i18n` (si opcion A) con `prefixDefaultLocale: false`.
3. Switcher funcional en el header (reemplaza el placeholder "Idioma"):
   link/select ES|EN que preserva la ruta (`/en/...`).

### Fase 3 — Migracion de UI a cadenas
1. `Header.astro`, `Footer.astro`, `BaseLayout.astro` (title/description, `lang`).
2. Home (`index.astro`) y secciones principales.
3. Vistas nuevas ya en `dev` (multimedia, academia, flota, tienda, donaciones, blog/noticias).
4. Paginas con mucho contenido institucional: traducir los `.md` o marcar "solo ES".

### Fase 4 — SEO
- `hreflang` (`es`/`en`), `lang` correcto en `<html>`, sitemap con URLs por locale.
- Meta `title`/`description` por locale.

### Fase 5 — Validacion
- `pnpm check`, `pnpm build` (rutas `/` y `/en/...` OK).
- Sin texto en espanol hardcodeado en la UI (grep de labels).
- Switcher conserva la ruta; accesible y con estado activo claro.

## Archivos a crear/modificar

- `pnpm check` 0 errores, `pnpm build` OK.
- `/` en espanol y `/en/` en ingles (o al menos switcher funcional segun opcion elegida).
- `lang` y `hreflang` correctos.
- No regresiones visuales en el header con el switcher.
